# 05 — Internationalization: Polish and English

## Goal

The product must support Polish and English from the start.

Locales:

- `pl` — Polish, default for Poland;
- `en` — English.

## Routing

Use locale-based routes:

```text
/pl/booking
/en/booking
/pl/admin/calendar
/en/admin/calendar
```

This is clearer than storing language only in local storage.

## Recommended library

Use `next-intl` or a simple dictionary-based approach.

Recommendation for MVP:

- use `next-intl` if you want robust locale routing and server/client translation helpers;
- use simple JSON dictionaries only if you want fewer dependencies.

## Implemented namespaces (Milestone 2)

The booking flow ships these `next-intl` namespaces in both `pl.json` and `en.json`:

- `home` — landing copy plus the `bookCta` button.
- `booking` — page, date/slot pickers, form labels, the optional-message medical-data warning, and consent text.
- `booking.errors` — stable validation/error **codes** (e.g. `required`, `invalidEmail`, `tooLong`, `consentRequired`, `invalidSlot`, `slotUnavailable`). The Zod schema and server action return these codes; the UI translates them, so server logic stays locale-agnostic.
- `booking.confirmation` — confirmation page copy.
- `emails.bookingConfirmation` — confirmation email subject/body.
- `emails.doctorNewBooking` — internal new-booking notification sent to the doctor/clinic (subject, labels for the patient details, and an admin-panel link). Rendered in the clinic's default locale, not the patient's.

## Implemented namespaces (Milestone 3)

The cancellation flow adds these namespaces in both `pl.json` and `en.json`:

- `cancel` — cancel page copy (title, appointment date/time line, confirm prompt/button, success, and the invalid / already-cancelled / cannot-cancel states) plus a re-book link.
- `cancel.errors` — stable cancel error **codes** (`notFound`, `notCancellable`, `unexpected`) returned by the server action and translated in the UI.
- `emails.cancellationConfirmation` — cancellation email subject/body with a re-book link.
- `emails.appointmentRescheduled` — reschedule notice sent to the patient when the doctor moves a booked appointment (subject, previous/new time labels, and a self-cancellation link).

Dates on the cancel page and in the cancellation email are formatted per locale in the appointment timezone (e.g. `June 8, 2026 at 9:00 AM` vs `8 czerwca 2026 09:00`).

## Implemented namespaces (Milestone 4)

The admin area adds one `admin` namespace in both `pl.json` and `en.json`:

- `admin.nav` — admin header (brand, calendar/new-appointment links, "signed in as", logout).
- `admin.login` — sign-in copy plus the `invalidCredentials` message (the only login error, used for every credential failure).
- `admin.calendar` — day-view labels (title, prev/today/next, date go button, empty state).
- `admin.appointment` — appointment detail labels and the not-found state, plus `admin.appointment.actions` (mark completed / no-show / cancel, and the reschedule form labels).
- `admin.manual` — manual-appointment form labels, the internal-note warning, and the optional patient-confirmation checkbox (`notifyLabel`, `notifyHint`).
- `admin.status` / `admin.source` — display labels for every `AppointmentStatus` and `AppointmentSource` value.
- `admin.errors` — stable manual-appointment error **codes** (`required`, `invalidEmail`, `invalidDate`, `invalidTime`, `tooLong`, `slotUnavailable`, `notConfigured`, `unexpected`) returned by the server action and translated in the UI.

Admin calendar/detail dates and times are formatted per locale in the doctor/clinic timezone.

## Implemented namespaces (Milestone 5)

The availability page extends the `admin` namespace in both `pl.json` and `en.json`:

- `admin.nav.settings` — the "Availability" admin-nav link.
- `admin.settings` — the Availability page: working-hours and blocked-time section copy, the `From`/`To` labels, save/add/remove buttons with their pending states, success messages, the `weekdays.1`–`weekdays.7` labels, and the `notConfigured` empty state.
- `admin.errors.endBeforeStart` — added stable error code for working-hours and blocked-time intervals whose end is not after their start.

Blocked-time entries are formatted per locale in the clinic timezone.

## Implemented namespaces (Milestone 6)

Patient history, internal notes, and CSV export extend the `admin` namespace in both `pl.json` and `en.json`:

- `admin.nav.patients` — the "Patients" admin-nav link.
- `admin.patients` — the patient list and detail pages: titles/subtitles, the export section copy, the `visits` count (an ICU plural, with Polish `one`/`few`/`many` forms), `lastVisit`, contact labels, copy-contact button, the not-found state, and the visit-history empty state.
- `admin.notes` — the internal-notes UI: section/add titles, the textarea placeholder, the GDPR/RODO `warning`, the add/saved/empty states, the `forVisit` ("Linked to a visit") tag, and the copy-visit-summary button.
- `admin.export` — the CSV export form: `From`/`To` labels and the download button.
- `admin.appointment.viewPatient` — the "View patient history" link on the appointment detail page.
- `admin.errors.invalidRange` — added stable error code for an export date range whose end precedes its start.

Visit dates/times and note timestamps are formatted per locale in the clinic timezone. The exported CSV is data-only (status/source are stored as their enum values, not translated).

## Implemented namespaces (Milestone 7)

GDPR/RODO hardening adds a public `privacy` namespace and extends `common`, `booking`, and `admin` in both `pl.json` and `en.json`:

- `privacy` — the public privacy policy page (`/[locale]/privacy`): `title`, `lastUpdated` (with a `{version}` placeholder), `intro`, nine `sections.*` title/body pairs (controller, data processed, purpose, legal basis, recipients, retention, rights, voluntary, security), `contactNotice`, `backHome`, and `bookCta`.
- `common.privacyPolicy` — the privacy-policy link label (home page).
- `booking.privacyLinkLabel` — the privacy-policy link shown under the booking consent checkbox.
- `admin.patients` — added the data-rights UI keys: `dataTitle`, `dataSubtitle`, `exportData`, `anonymizeTitle`, `anonymizeWarning`, `anonymizeConfirm`, `anonymizeCta`, `anonymizing`, `anonymizedBadge`, `anonymizedNotice`, `anonymizeDone`.
- `admin.errors` — added stable codes `confirmRequired`, `patientHasFutureAppointments`, and `alreadyAnonymized`.

The privacy page shows `PRIVACY_TEXT_VERSION` as its version. Stored anonymization placeholders (`Anonymized`, `Patient`) are locale-independent data, not UI strings.

## Translation rules
2. All buttons, labels, error messages, emails, and validation messages must be translated.
3. Admin and patient UI both need translations.
4. Emails must use the appointment locale when possible.
5. Validation errors must be user-friendly and localized.

## Language switcher

Add a simple language switcher:

```text
PL | EN
```

Rules:

- switch should preserve current page where possible;
- if a route does not exist in target locale, go to locale home.

## Date/time localization

Display dates according to locale:

Polish:

```text
12 czerwca 2026, 15:00
```

English:

```text
June 12, 2026, 3:00 PM
```

Store timestamps as timestamps, not localized strings.

## Email localization

Emails are localized through the same `next-intl` message catalogs, not separate
template modules. The booking confirmation lives under the `emails.bookingConfirmation`
namespace and is rendered server-side with `getTranslations({ locale, namespace })`
in `src/server/email/sendBookingConfirmation.ts`, using the patient's booking locale.

```text
src/i18n/messages/pl.json  →  emails.bookingConfirmation
src/i18n/messages/en.json  →  emails.bookingConfirmation
```

or use dictionary-based templates.

Email types:

- booking confirmation;
- doctor notification;
- cancellation confirmation;
- reminder later.

## Admin language

Doctor can choose preferred admin language in settings.

MVP default:

- clinic default locale = `pl`;
- allow manual switch to `en`.

## Implementation status (Milestone 0)

The i18n foundation is implemented with `next-intl`:

- `src/i18n/routing.ts` — locales `["pl", "en"]`, default `pl`.
- `src/i18n/request.ts` — loads `src/i18n/messages/{locale}.json`.
- `src/i18n/navigation.ts` — locale-aware `Link`, `redirect`, `usePathname`, `useRouter`.
- `src/proxy.ts` — locale routing middleware (Next.js 16 `proxy` file convention).
- `src/app/[locale]/layout.tsx` and `page.tsx` — localized layout and home page.
- `next.config.ts` — wrapped with `createNextIntlPlugin("./src/i18n/request.ts")`.

Verified: `/` redirects to `/pl`; `/pl` and `/en` render localized content with the
correct `<html lang>`. A `PL | EN` language switcher lives in
`src/components/locale-switcher.tsx`.
